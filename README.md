# AITo麻雀（エイトマージャン）— React Three Fiber 3D技術検証 PoC

> ITの知識を武器に、AIと役を創る、新感覚麻雀。

React Three Fiber で「本格的な3D麻雀卓と牌操作」をブラウザ上に作れるかを検証するプロトタイプです。
対局ルール・AI判定・オンライン対戦は含みません（将来の開発対象）。

---

## 必要環境

| 項目 | バージョン |
|---|---|
| OS | Windows 11（macOS / Linux でも動作する構成） |
| Node.js | 20 LTS 以上（22 LTS 推奨） |
| npm | Node.js 同梱版 |
| ブラウザ | 最新の Chrome / Edge（WebGL 2 必須） |
| スマホ | **横画面専用**（縦向きでは回転を促す案内を表示） |

## 起動方法（PowerShell）

```powershell
cd aito-mahjong
npm install        # 初回のみ
npm run dev        # 開発サーバー起動 → 表示された http://localhost:5173 を開く
```

その他のコマンド:

```powershell
npm run typecheck  # TypeScript の型チェックのみ
npm run build      # 型チェック + 本番ビルド（dist/ に出力）
npm run preview    # ビルド結果をローカルで確認
```

> `package.json` の各ライブラリは、互換性を確認済みの組み合わせ（React 19 / R3F 9 / drei 10 / three r176 / Vite 6）で指定しています。
> 最新版に上げる場合は `npm install three@latest @types/three@latest @react-three/fiber@latest @react-three/drei@latest` の後に `npm run build` で確認してください。

## 操作方法

| 操作 | マウス / タッチ | キーボード |
|---|---|---|
| 牌を選択 | 牌をクリック / タップ | ← → で選択を移動 |
| 選択解除 | 同じ牌をもう一度クリック | Esc |
| 打牌 | 牌を選択して「打牌」ボタン | Enter / Space |
| IT用語解説 | PC: 牌にカーソルを合わせる / 選択中の牌は左下パネルに常時表示 | — |
| 関連技術を見る | 解説パネルの色付きチップをクリック | — |
| カメラ回転・ズーム | ドラッグ / ホイール（スマホはピンチ） | — |
| カメラリセット | 「カメラリセット」ボタン | R |
| 配り直し | 「配り直す」ボタン | — |
| カテゴリ名の表示切替 | 右上のスイッチ | — |
| 全画面（スマホ） | 右上の「全画面」ボタン（対応ブラウザのみ） | — |

**タッチ操作の設計**：タップは「牌の選択」だけに割り当て、打牌は必ずボタンで行います。
選択した牌の解説は左下パネルに出るため、「解説を読もうとして誤って牌を捨てる」ことが起きません。
ホバー解説はマウス操作時のみ表示します。

### スマホ（横画面）

- スマホは横画面でプレイします。縦向きで開くと「端末を横向きにしてください」と表示し、その間は3D描画を止めて電池を節約します。
- 横画面では手牌に寄ったカメラ構図に自動で切り替わり、手牌が画面幅の約9割に大きく表示されます（844×390 の画面で牌1枚 約57px）。
- UIは手牌に重ならない位置に配置します：設定は右上に1行、解説パネルは左上、打牌ボタンは右手の親指が届く右側中段。
- ノッチ（画面の切り欠き）がある端末でも、UIが隠れないよう左右の余白を自動で確保します。
- Android の Chrome などでは「全画面」ボタンでアドレスバーを隠し、横向きに固定できます（iPhone の Safari は Fullscreen API 非対応のためボタンを出しません）。

## 実装機能

- **3D麻雀卓**：外枠（濃紺・クリアコート）、深緑フェルト（回路パターンが呼吸するように発光）、外枠内周のシアン装飾ライト、中央コンソール（風表示）とホログラムリング、台座、電脳空間風の床グリッド、他家の手牌（装飾）
- **共通3D牌モデル**：角丸・2層構造（象牙色の本体＋濃いブルーの背）、本体と牌面で質感を分離、影あり
- **牌面**：カテゴリ色の帯／オリジナルアイコン／技術名（長い名前は改行・自動縮小）。Canvas で生成
- **9カテゴリ×色**、複数カテゴリ所属のデータ構造（牌の色は主分類）
- **13枚の手牌**：配牌演出、選択で持ち上げ＋発光、再クリックで解除、1枚のみ選択
- **打牌**：放物線＋ひねり回転で河へ移動 → 着地で衝撃波リング・光の柱・粒子・牌面フラッシュ → 河に残る（最新の捨て牌にマーカー）
- **IT用語解説**：ホバー解説（PC）、選択中の牌の解説パネル、関連技術のプレビュー
- **UI**：タイトル、打牌ボタン、配り直し、カメラリセット、カテゴリ表示ON/OFF、効果音ON/OFF、凡例、操作方法
- **演出**：起動時のカメラフライイン、リセット時の滑らかな復帰、卓上の浮遊粒子、合成効果音（Web Audio）
- **品質面**：打牌中の多重操作をロジック側でロック、フレームレート非依存アニメーション、ウィンドウサイズに応じた自動構図調整、WebGL 2 非対応時の案内
- **スマホ横画面対応**：専用カメラ構図、手牌を避けたUI配置、縦向き時の回転案内（描画停止）、ノッチ対策、全画面ボタン

## 設計メモ

### 状態管理と再レンダリング
- ゲーム状態は `useReducer`（`gameReducer.ts`）に集約。`flying`（打牌中）の間は `LAND` 以外のアクションを全て無視するため、ボタン連打・キー連打でも二重打牌が起きない。
- 牌の位置・発光などの毎フレーム変化する値は `useFrame` 内で ref を直接更新し、React の再レンダリングは選択・打牌など離散イベント時だけに限定。
- ホバー中の用語は App の state だが、3D側（`MahjongScene` は `memo`）に渡す props は変わらないので3Dは再レンダリングされない。ホバー解説のカーソル追従も DOM を直接更新。

### アニメーション
- 選択・ホバー・手牌の詰め直しは `THREE.MathUtils.damp`（経過時間ベースの指数減衰）で追従 → フレームレート非依存。
- 打牌は「進行度 = 経過時間 / 0.62秒」で計算。水平は easeInOutCubic、高さは放物線、ひねりは sin 波で着地時に0へ戻る。
- 手牌の実際の表示姿勢を `TileTransformRegistry` に毎フレーム書き込み、打牌時はその姿勢から飛び立たせる（持ち上げ途中で打牌してもワープしない）。

### カメラ構図（PC とスマホ横画面）
- 高さ 500px 以下の横長画面を「スマホ横画面」と判定し、`CAMERA_COMPACT`（画角56°・手牌に近いカメラ）に切り替える。画角を広げてカメラを近づけると、遠近感で手前の手牌が大きく・奥の卓が小さく映る。
- 値は透視投影の計算で決めた。主な画面サイズでの計算結果（手牌の横範囲／牌1枚の幅）:
  844×390: 6〜94% / 約57px、915×412: 7〜93% / 約60px、740×360: 7〜93% / 約49px、667×375（iPhone SE）: 10〜90% / 約42px
- 基準より縦長の画面ではカメラを少し引いて、手牌が画面からはみ出さないようにする。
- 構図の切り替え（回転・リサイズ）はユーザーがカメラを触っていなければ滑らかに追従する。

### GPU負荷への配慮
- 牌のジオメトリ・本体マテリアルは全牌で共有。牌面テクスチャは「用語×カテゴリ表示」ごとに1枚だけ生成してキャッシュ。
- 他家の手牌39枚は InstancedMesh（2ドローコール）。
- 環境マップは外部HDRを読まず、Lightformer を1回だけ焼き込む（`frames={1}`）。
- `dpr={[1, 2]}`、影は1灯のみ（2048px）。

### アセット・権利
- 画像・音声・フォントファイルは使用していません。牌面・卓の模様・アイコンは全て Canvas でのオリジナル描画、効果音は Web Audio による合成音です。
- 技術名のロゴ（商標）は使わず、技術の役割を表す汎用モチーフ（ハンドシェイク図、錠前、コンテナ等）で表現しています。
- フォントは OS 標準フォント（Segoe UI / Yu Gothic UI / Meiryo / ヒラギノ等）を使用。

### 拡張ポイント
- **用語の追加**：`src/data/terms.ts` に追記。参照は `getTerm()` / `findTermByName()` 経由なので、約1,000語規模で JSON 分割・動的読み込みに変えても呼び出し側は変更不要。
- **アイコンの追加**：`TileIconId` に ID を足し、`tileIcons.ts` に描画関数を追加。
- **14枚表示**：`handSlotX(index, count, withDrawnTile)` の第3引数でツモ牌を離して配置できる。
- **演出の差し替え**：着地エフェクトは `ImpactEffectProps`（位置・色・終了通知）だけを受け取る独立コンポーネント。リーチ・役満演出も同じ形で追加できる。

## 既知の問題・未実装

- 上記のとおり、3D描画部分は実機ブラウザでの確認が未実施です。カメラ位置・ライト強度・エフェクトの大きさは計算上の値なので、実際に見て微調整が必要になる可能性があります。
- ツモ・牌山・他家の打牌は未実装（仕様どおり）。打牌を続けると手牌が減るので「配り直す」で再開します。
- スマホ横画面の構図は計算値です。実機でアドレスバーの有無により画面の高さが変わるため、見え方を確認して `CAMERA_COMPACT` を微調整してください。
- スマホでは影・解像度を下げるなどの負荷対策（品質設定の自動切替）はまだ入れていません。
- ポストプロセス（ブルーム等）は使っていません。発光は加算合成とトーンマッピング無効のマテリアルで表現しています。

## 次の開発ステップ

1. 実機で起動し、カメラ・ライト・エフェクトの見た目を調整
2. ツモ（牌山から1枚引いて14枚表示）→ 打牌のサイクルを実装
3. ブルーム等のポストプロセス（`@react-three/postprocessing`）の導入と負荷計測
4. 用語辞書を 50〜200 語に拡張し、JSON 化と遅延読み込みを検証
5. 面子判定のルール設計（「技術的な関係性」をどうデータ化するか）
6. 他家（CPU）の打牌アニメーションと河の表示
7. スマホ実機での負荷計測と、品質設定（影・解像度）の自動切替
8. Unity 版の同等プロトタイプを作り、上の比較表で評価
