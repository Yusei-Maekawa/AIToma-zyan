# AITo麻雀（エイトマージャン）— React Three Fiber 3D技術検証 PoC

> ITの知識を武器に、AIと役を創る、新感覚麻雀。

React Three Fiber で「本格的な3D麻雀卓と牌操作」をブラウザ上に作れるかを検証するプロトタイプです。
対局ルール・AI判定・オンライン対戦は含みません（将来の開発対象）。

---

## 必要環境

| 項目 | バージョン |
|---|---|
| OS | Windows 11（macOS / Linux でも動作する構成） |
| Node.js | 20 LTS 以上（22 LTS 推奨） |
| npm | Node.js 同梱版 |
| ブラウザ | 最新の Chrome / Edge（WebGL 2 必須） |

## 起動方法（PowerShell）

```powershell
cd AIToma-zyan
npm install        # 初回のみ
npm run dev        # 開発サーバー起動 → 表示された http://localhost:5173 を開く
```

スマホ（同じ Wi-Fi）から開く場合:

```powershell
npx vite --host    # 表示された「Network: http://192.168.x.x:5173/」をスマホで開く
```

- PowerShell で `npm run dev -- --host` と書くと `--` が消えて `--host` が届かないことがあるため、`npx vite --host` を使います。
- PC の Wi-Fi が「パブリック ネットワーク」だとファイアウォールで遮断されます。自宅の Wi-Fi なら「プライベート」に切り替えてください（設定 → ネットワークとインターネット → Wi-Fi → 接続中のネットワークのプロパティ）。

その他のコマンド:

```powershell
npm run typecheck  # TypeScript の型チェックのみ
npm run test       # アガリ判定の単体テスト
npm run build      # 型チェック + 本番ビルド（dist/ に出力）
npm run preview    # ビルド結果をローカルで確認
```

> `package.json` の各ライブラリは、互換性を確認済みの組み合わせ（React 19 / R3F 9 / drei 10 / three r176 / Vite 6）で指定しています。
> 最新版に上げる場合は `npm install three@latest @types/three@latest @react-three/fiber@latest @react-three/drei@latest` の後に `npm run build` で確認してください。

## 操作方法

| 操作 | マウス / タッチ | キーボード |
|---|---|---|
| ツモ | 「ツモ」ボタン（手牌13枚・牌山が残っているときのみ） | T |
| 牌を選択 | 牌をクリック / タップ（13枚のときも選んで解説を読める） | ← → で選択を移動 |
| 選択解除 | 同じ牌をもう一度クリック | Esc |
| 打牌 | ツモ後（14枚）に牌を選択して「打牌」ボタン | Enter / Space |
| IT用語解説 | PC: 牌にカーソルを合わせる / 選択中の牌は左下パネルに常時表示 | — |
| 関連技術を見る | 解説パネルの色付きチップをクリック | — |
| カメラ回転・ズーム | ドラッグ / ホイール（スマホはピンチ） | — |
| カメラリセット | 「カメラリセット」ボタン | R |
| 配り直し | 「配り直す」ボタン。アガリ後は「もう一度」 | — |
| カテゴリ名の表示切替 | 右上のスイッチ | — |
| 画質 | 右上の「高／中／低」（FPS が低いと自動で1段下がる） | — |
| 描画情報 | URL に `?debug` を付けたときだけ、画面上部に FPS・dpr・ドローコール・三角形数 | — |
| 全画面（スマホ） | 右上の「全画面」ボタン（対応ブラウザのみ） | — |

**タッチ操作の設計**：タップは「牌の選択」だけに割り当て、打牌は必ずボタンで行います。
選択した牌の解説は左下パネルに出るため、「解説を読もうとして誤って牌を捨てる」ことが起きません。
ホバー解説はマウス操作時のみ表示します。

### スマホ（横画面）

- スマホは横画面でプレイします。縦向きで開くと「端末を横向きにしてください」と表示し、その間は3D描画を止めて電池を節約します。
- 横画面では手牌に寄ったカメラ構図に自動で切り替わり、手牌が画面幅の約9割に大きく表示されます（844×390 の画面で牌1枚 約57px）。
- UIは手牌に重ならない位置に配置します：設定は右上に1行、解説パネルは左上、ツモ・打牌ボタンは右手の親指が届く右側中段。
- ノッチ（画面の切り欠き）がある端末でも、UIが隠れないよう左右の余白を自動で確保します。
- Android の Chrome などでは「全画面」ボタンでアドレスバーを隠し、横向きに固定できます（iPhone の Safari は Fullscreen API 非対応のためボタンを出しません）。

## 実装機能

- **3D麻雀卓**：外枠（濃紺・クリアコート）、深緑フェルト（回路パターンが呼吸するように発光）、外枠内周のシアン装飾ライト、中央コンソール（風表示）とホログラムリング、台座、電脳空間風の床グリッド、他家の手牌（装飾）。4人分の河を4段まで並べても四隅で重ならない広さ
- **共通3D牌モデル**：角丸・2層構造（象牙色の本体＋濃いブルーの背）、本体と牌面で質感を分離、影あり
- **牌面**：カテゴリ色の帯／オリジナルアイコン／技術名（長い名前は改行・自動縮小）。Canvas で生成
- **9カテゴリ×色**、複数カテゴリ所属のデータ構造（牌の色は主分類）
- **手牌**：13枚の配牌演出、選択で持ち上げ＋発光、再クリックで解除、1枚のみ選択
- **ツモ → 打牌のサイクル**：牌山から1枚引いて14枚にし、14枚のときだけ打牌できる（13枚での打牌は reducer が無視）。ツモ牌は右端に少し離して置き、手出しした場合はツモ牌を手牌に加えて自動で理牌（並べ替え）する
- **牌山**：全36枚（9種×4枚）から13枚を配った残り23枚。卓の奥の左の隅に裏向き2段で積み、ツモのたびに減る。ツモ牌は山から弧を描いて起き上がりながら手牌の右端へ飛んでくる
- **打牌**：放物線＋ひねり回転で河へ移動 → 着地で衝撃波リング・光の柱・粒子・牌面フラッシュ → 河に残る（最新の捨て牌にマーカー）
- **ツモ和了**：14枚が「面子4つ＋同じ牌のペア」ならその場で終了。面子は同じ牌3枚、または登録した関係のある3枚（Python・FastAPI・PostgreSQL／React・FastAPI・PostgreSQL／Python・LLM・Docker）。役・点数・鳴き・リーチ・ロンはなし。アガリ中はツモ・選択・打牌を拒否し、「もう一度」で配り直す
- **IT用語解説**：ホバー解説（PC）、選択中の牌の解説パネル、関連技術のプレビュー
- **UI**：タイトル、ツモ・打牌ボタン、手牌／牌山／河の枚数表示、配り直し、カメラリセット、画質（高／中／低）、カテゴリ表示ON/OFF、効果音ON/OFF（起動時はオフ）、凡例、操作方法。牌山が空のときはツモを止め、「配り直す」を案内する
- **演出**：起動時のカメラフライイン、リセット時の滑らかな復帰、卓上の浮遊粒子、合成効果音（Web Audio）
- **品質面**：打牌中のツモ・選択・打牌をロジック側でロック、フレームレート非依存アニメーション、ウィンドウサイズに応じた自動構図調整、WebGL 2 非対応時の案内。画質は高／中／低（dpr 上限・影・粒子・環境マップ）。タッチ端末は中、メモリ 4GB 以下は低から開始し、FPS が低いと自動で1段だけ下げる（上げるのは手動）。`?debug` で FPS・dpr・ドローコール・三角形数を表示
- **スマホ横画面対応**：専用カメラ構図、手牌を避けたUI配置、縦向き時の回転案内（描画停止）、ノッチ対策、全画面ボタン

## 設計メモ

### 状態管理と再レンダリング
- ゲーム状態は `useReducer`（`gameReducer.ts`）に集約。`flying`（打牌中）の間は `LAND` 以外のアクションを全て無視するため、ボタン連打・キー連打でも二重打牌・打牌中のツモが起きない。
- ツモ牌は `hand` に混ぜず `drawn` という別フィールドに持つ。`hand` は常に「理牌済みの13枚」という不変条件を保ち、「打牌できるか」は `drawn !== null` だけで判定できる。
- 牌山（`wall`）は配牌時にシャッフルと uid の付与まで済ませて state に持ち、`DRAW` は先頭から1枚取るだけ。uid は配牌番号と山の位置から決め、乱数の seed は App 側で作って `REDEAL` に渡す。開発時の StrictMode は reducer を2回呼ぶため、reducer の中では乱数・時刻・外部カウンタを使わない。
- ツモ牌も手牌と同じ配列・同じ `key` で描画する。手出しで手牌に合流しても再マウントされず、理牌位置まで滑って移動する。
- 牌の位置・発光などの毎フレーム変化する値は `useFrame` 内で ref を直接更新し、React の再レンダリングは選択・打牌など離散イベント時だけに限定。
- ホバー中の用語は App の state だが、3D側（`MahjongScene` は `memo`）に渡す props は変わらないので3Dは再レンダリングされない。ホバー解説のカーソル追従も DOM を直接更新。

### アニメーション
- 選択・ホバー・手牌の詰め直しは `THREE.MathUtils.damp`（経過時間ベースの指数減衰）で追従 → フレームレート非依存。
- 打牌は「進行度 = 経過時間 / 0.62秒」で計算。水平は easeInOutCubic、高さは放物線、ひねりは sin 波で着地時に0へ戻る。
- ツモは「進行度 = 経過時間 / 0.7秒」で、牌山のマス（裏向き）から手牌の右端へ放物線で飛び、起き上がりながら牌面を見せる。着地後は通常の `damp` による追従に引き継ぐ。ツモ後の牌山の残り枚数 n が「今引いた牌があったマス番号」と一致するので、山から消えるマスと飛び立つ位置が必ずそろう。
- 手牌の実際の表示姿勢を `TileTransformRegistry` に毎フレーム書き込み、打牌時はその姿勢から飛び立たせる（持ち上げ途中やツモの飛行中に打牌してもワープしない）。

### 卓の寸法
- 河は1段6枚で、開始位置（中心から1.75）を河の幅の半分（約1.66）より外にしている。4人分の河を4段（牌山23枚を捨て切った枚数）まで並べても、四隅で隣の河と重ならない。
- 手牌は河の4段目が陰に隠れない距離（中心から5.55）に置き、卓（フェルトの半辺6.3）をそれに合わせて広げた。
- 卓を広げてカメラを引いた分、手牌の拡大率を 1.45 にして、画面上の手牌の大きさ（文字の読みやすさ）を保っている。河の牌は以前より約2割小さく映る。

### カメラ構図（PC とスマホ横画面）
- 高さ 500px 以下の横長画面を「スマホ横画面」と判定し、`CAMERA_COMPACT`（画角56°・手牌に近いカメラ）に切り替える。画角を広げてカメラを近づけると、遠近感で手前の手牌が大きく・奥の卓が小さく映る。
- 値は透視投影の計算で決めた。主な画面サイズでの計算結果（手牌の横範囲／牌1枚の幅）:
  844×390: 6〜94% / 約57px、915×412: 7〜93% / 約60px、740×360: 7〜93% / 約49px、667×375（iPhone SE）: 10〜90% / 約42px
- 卓の拡大時は、手牌に対するカメラの相対位置が同じになるよう `CAMERA_COMPACT` を平行移動・拡大して移した（上の計算結果は変わらない想定。画面では未確認）。
- 基準より縦長の画面ではカメラを少し引いて、手牌が画面からはみ出さないようにする。
- 構図の切り替え（回転・リサイズ）はユーザーがカメラを触っていなければ滑らかに追従する。

### GPU負荷への配慮
- 牌のジオメトリ・本体マテリアルは全牌で共有。牌面テクスチャは「用語×カテゴリ表示」ごとに1枚だけ生成してキャッシュ。
- 他家の手牌39枚・牌山24マスはそれぞれ InstancedMesh（各2ドローコール）。牌山はツモで作り直さず、描画数（`count`）を減らすだけ。
- 環境マップは外部HDRを読まず、Lightformer を1回だけ焼き込む（`frames={1}`）。
- `dpr={[1, 2]}`、影は1灯のみ（2048px）。

### アセット・権利
- 画像・音声・フォントファイルは使用していません。牌面・卓の模様・アイコンは全て Canvas でのオリジナル描画、効果音は Web Audio による合成音です。
- 技術名のロゴ（商標）は使わず、技術の役割を表す汎用モチーフ（ハンドシェイク図、錠前、コンテナ等）で表現しています。
- フォントは OS 標準フォント（Segoe UI / Yu Gothic UI / Meiryo / ヒラギノ等）を使用。

### 拡張ポイント
- **用語の追加**：`src/data/terms.ts` に追記。参照は `getTerm()` / `findTermByName()` 経由なので、約1,000語規模で JSON 分割・動的読み込みに変えても呼び出し側は変更不要。
- **アイコンの追加**：`TileIconId` に ID を足し、`tileIcons.ts` に描画関数を追加。
- **演出の差し替え**：着地エフェクトは `ImpactEffectProps`（位置・色・終了通知）だけを受け取る独立コンポーネント。リーチ・役満演出も同じ形で追加できる。

## 既知の問題・未実装

- 3D描画は PC ブラウザでのみ確認しています。スマホ実機では未確認です。
- 他家の打牌は未実装（仕様どおり）。他家は装飾で、河を使うのは自分だけです。牌山を使い切ったら「配り直す」で再開します（流局の処理はありません）。
- アガリはツモ和了だけです。ロン・リーチ・鳴き・点数はありません。起動時の固定配牌はツモ切りではアガりにくいので、確認は「配り直す」からがわかりやすいです。
- 牌山は卓の隅に置いた小さな山（4列×3行×2段）で、本物の麻雀のように4辺を囲む山ではありません。
- 高さの低い PC の画面では、左下の解説パネルと手牌の左端が近く、重なる可能性があります。
- スマホ横画面の構図は計算値です。実機でアドレスバーの有無により画面の高さが変わるため、見え方を確認して `CAMERA_COMPACT` を微調整してください。
- 画質は高／中／低を手動で切り替えられ、直近120フレームの平均 FPS が40未満の状態が2秒続くと1段だけ自動で下がります。上がるのは手動だけです。アンチエイリアスは起動時のまま（切替では変わりません）。実機での負荷低減は未確認です。
- ポストプロセス（ブルーム等）は使っていません。発光は加算合成とトーンマッピング無効のマテリアルで表現しています。
